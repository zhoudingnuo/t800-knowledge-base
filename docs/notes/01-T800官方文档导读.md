## 一、t800-developer/（T800 开发版硬件，7 页）

**栏目定位**：T800 开发版（基础版，25 自由度、无灵巧手）的整机硬件与结构资料，用于选型、接线、装配与仿真建模核对。

### [01-关于T800（开发版）.md](../t800-online/t800-developer/01-关于T800（开发版）.md)
- 标题：1. 关于T800（开发版）
- 核心：T800 系列定位工业/商业落地的高动态、高负载人形作业平台，支持负重搬运、奔跑、精细操作与二次开发。
- 构型说明：单腿 6 自由度（髋 3+膝 1+踝 2）、腰部 1、头部 2；单臂基础版 5 自由度，PRO/MAX 版增加腕部自由度。
- 版本自由度：基础版 25、PRO 版 29、MAX 版配灵巧手后最高 43；关节电机（行星/谐波）最高 450 N·m。
- 整机型号配置图以图片给出，正文未列具体配置表（文档未提及文字版配置）。

### [02-机器人规格&电气接口.md](../t800-online/t800-developer/02-机器人规格&电气接口.md)
- 标题：2. 机器人规格&电气接口
- 核心：开发版规格为身高 173cm、带电约 84.5kg、大小腿 91cm、大臂+小臂 60cm，总自由度 25。
- 运动能力：前进 0~1.5m/s、后退 0~0.8m/s、侧移 0~0.5m/s、左右转 0~20°/s、硬件支持跑步 <3m/s；最大坡度 20°、可跨越 20cm。
- 电气/结构：全关节中空走线、绝对式双编码器、行星关节、腿关节峰值扭矩 450 N·m，工作温度 -10~40℃。
- 算力配置：基础算力 NAZHA，高算力 NVIDIA Jetson AGX Orin 64GB、64G 内存、256G SSD，支持二次开发。
- 电池：三元锂 1.22kWh、续航 2h（标配）、充电 71.4V*10A、2.5h；灵巧手不支持。
- 外部接口仅 3 个：USB A 3.0（内部连 AGX Orin，5V/1A）、USB A 3.0（内部连 NeZha N97，5V/1A）、RJ45 千兆网口；不支持外部供电与机身充电。

### [02-运动状态机.md](../t800-online/ros2-interface/02-运动状态机.md)
- 标题：2. 运动状态机
- 核心：所有控制接口的前置条件；订阅 `/motion/motion_state`（`MotionState.msg`，字段 `current_motion_task`、`available_transition_motions`）读取状态，向 `/motion/set_motion_state`（`MotionStateRequest.msg`，字段 `target_motion_name`）发切换请求。
- 状态清单（17 种）：`idle`/`passive`/`pd_stand`/`rl_basic`/`lower_body_balance`/`joint_bridge`/`pd_sitground` 为 PM01+T800；`rl_amp`/`rl_terrain`/`rl_recover_prone`/`rl_floor_sitting` 仅 PM01；`walk_server` 与 5 种 `rl_mimic_*` 仅 T800。
- 规则：目标必须在 `available_transition_motions` 内；每次只发一条请求；切换 3 秒超时；可能需要中间状态（如 idle→rl_terrain 经 pd_stand）。
- QoS：发布切换用 RELIABLE/VOLATILE，订阅状态用 BEST_EFFORT/VOLATILE。
- 示例：`switch_to_terrain_walking_gait_example.py -m lower_body_balance`（同目录另有 `switch_to_target_motion_example.py`）。
- 关键接口：`/motion/motion_state`、`/motion/set_motion_state`；手柄切 `joint_bridge`=[BACK,A]。

### [03-关节命令与全身控制.md](../t800-online/ros2-interface/03-关节命令与全身控制.md)
- 标题：3. 关节命令与全身控制
- 核心：最底层关节级接口，向 `/hardware/joint_command`（`JointCommand.msg`）发位置/速度/前馈力矩/kp/kd，从 `/hardware/joint_state`（`JointState.msg`）读位置/速度/力矩。
- `JointCommand` 字段：`position`、`velocity`、`feed_forward_torque`、`torque`（暂不支持）、`stiffness`、`damping`、`parallel_parser_type`（0=CLASSIC_PARSER，1=RL_PARSER）。
- 力矩公式：`tau = kp*(q_cmd-q) + kd*(qd_cmd-qd) + feed_forward_torque`；推荐 100~500Hz、Best Effort、数组长度=总关节数。
- 前置：必须进入 `joint_bridge`（关节透传，手柄 [BACK, A]）。
- 示例 A：`joint_bridge_example.py` + `config/{pm01,t800,t800pro}/pd_joint_test.yaml`（YAML 含 `target_position`/`kp`/`kd`/`num_steps`，线性插值，500Hz）。
- 示例 B：`ros2 launch interface_example rl_basic_example.launch.py`（RL 全身策略，输入关节状态+手柄+IMU，流程 pd_stand→joint_bridge→launch）。
- 示例 C：T800 Pro `t800pro/loose_fist_example.py --pose extend|loose_fist|both --hand left|right --exec-time --hold-time --rate`。
- 关键接口：`/hardware/joint_command`、`/hardware/joint_state`、`/hardware/gamepad_keys`、`/hardware/imu_info`。

### [04-机体速度控制.md](../t800-online/ros2-interface/04-机体速度控制.md)
- 标题：4. 机体速度控制
- 核心：较高层级的行走速度接口，向 `/motion/body_vel_cmd`（`BodyVelCmd.msg`）持续发布期望线速度与偏航角速度，内部行走控制器自动完成关节规划。
- 坐标系：右手系、原点机体中心，X 前进、Y 左侧、Z 向上；`header.frame_id="body"`。
- 字段与限幅：`linear_velocity[0]` X（±1 m/s）、`linear_velocity[1]` Y（±1 m/s）、`yaw_velocity`（±1 rad/s，逆时针为正）。
- 频率/停止：推荐 100Hz（最低 50Hz）；停止需显式发零速度；接收端 2 秒无消息自动停下。
- 前置模式与按键：`rl_basic`=[LB,B]（PM01/T800）、`rl_amp`=[LB,X]（仅 PM01）、`rl_terrain`=[LB,Y]（仅 PM01）、`lower_body_balance`=[LB,CROSS_X_DOWN]（PM01/T800）。
- 示例：`body_velocity_control_example.py`。
- 关键接口：`/motion/body_vel_cmd`。

### [05-上肢关节运动规划.md](../t800-online/ros2-interface/05-上肢关节运动规划.md)
- 标题：5. 上肢关节运动规划
- 核心：队列化上肢动作规划，"发一次请求、等待执行完成"；请求走 `/motion/joint_motion_plan/request`（`JointMotionPlanRequest.msg`），状态读 `/motion/joint_motion_plan/state`（`JointMotionPlanState.msg`）。
- 请求常量：`REQUEST_PLAN_EXECUTE=0`、`REQUEST_CANCEL=1`、`REQUEST_RESET=2`；状态常量：`STATUS_DISABLED=0`/`IDLE=1`/`EXECUTING=2`/`EXITING=3`，含 `request_id` 与 `progress(0~1)`。
- 字段：`joint_indices`、`target_positions`、`target_velocities`、`execution_time`、`stiffness`、`damping`、`use_gravity_compensation`。
- 前置：`lower_body_balance`（[LB, CROSS_X_DOWN]）；`request_id` 必须递增（当前+1）；任务串行、失败不自动重试。
- YAML 机型差异：PM01 规划索引 [12~23]（腰刚度 200）；开发版 [12~24]（腰 400）；Pro [12,13,14,15,16,17,27,28,29,30,31,41,42]（腰 500、阻尼 10）。
- 示例：`joint_mutiple_motion_plan_example.py -f config/{pm01,t800,t800pro}/motion_plan_shake_hand.yaml`。
- 异常：本页正文写作 `/joint_motion_plan_request`、`/joint_motion_plan_state`，与同页表格及 01 页的 `/motion/...` 前缀不一致；示例文件名正文有笔误 `joint_multiple``_motion_plan_example.py`。

### [06-上肢关节覆盖控制.md](../t800-online/ros2-interface/06-上肢关节覆盖控制.md)
- 标题：6. 上肢关节覆盖控制
- 核心：行走中实时控制上肢，"持续高频发布"（与 05 页"一次请求"互补）；向 `/motion/joint_override_command`（`JointOverrideCommand.msg`）发布，建议 100Hz。

- 异常：本页正文写作 `/joint_override_command` 和 `/joint_states`（`sensor_msgs`），与同页表格 `/motion/joint_override_command` 及 01 页 `/hardware/joint_state` 不一致。

### [07-LED-控制.md](../t800-online/ros2-interface/07-LED-控制.md)

### [3-源码解析.md](../t800-online/native-sdk/3-源码解析.md)
- 标题：3. 源码解析
- **目录结构要点**：
  - 顶层：`CMakeLists.txt`（自动识别 core 预编译包）、`build.sh/run.sh/clear.sh`、`install.sh`。
  - `src/executor/main.cc` 程序入口；`src/hardware/`（手柄驱动示例）、`src/protocol/`（ROS2 msg 示例）、`src/ros2_node/`（ROS2 收发示例）、`src/data/_param/`（参数解析类）。
  - `src/runner/`：`passive`（低阻抗输出）、`pd_stand`（PD 站立）、`input_command_arbiter`（输入源仲裁）、`ros2_bridge`（ROS2 数据交换）、`rl_dance_example`、`rl_walking_example`。
  - `assets/config/<robot>/`（mode + task + runner 参数）、`assets/resource/`（urdf/xml/mesh/策略模型）。
  - `core/` 预编译核心库（不要直接改）：`core/include/`、`core/lib/`、`core/registry/auto_register_runners.cc`；另有 `cmake/`、`simulation/mujoco/`、`scripts/`。
- **配置加载链路**：`assets/config/<robot>/mode.yaml` 是入口，`active_mode` 选 `sim/robot` → 建立 `tag -> scope` 映射（如 `pd_stand -> pd_stand/default`）→ `BasicParam(tag)` 按 tag 找到 scope → 参数类用 `LOAD_PARAM(xxx)` 读取 YAML 字段。
- **Task 与 Runner**：Task 是调度单元（线程、周期、优先级、`runner[]`）；`task_resident/*.yaml` 常驻并行，`task_motion/*.yaml` 同时刻只激活一个、按键或自动迁移。Runner 是算法执行单元，Task 按周期驱动其生命周期接口。
- **Runner 生命周期要点**（`core/include/basic/basic_runner.h`）：`Initialize()`（构造时一次）→ `Enter()`（进入任务，加载参数/模型）→ `Run()`（周期主逻辑）→ `TryExit()`（可持续多周期的退场复位，用 `kTrying/kCompleted` 反馈）→ `Exit()`（确认退出后一次性收尾）→ `End()`（生命周期结束）。
- **MotionRunner 增量**（`core/include/basic/motion_runner.h`）：`SetupContext()`/`TeardownContext()` 管理全局上下文；`GetMutableOutput().SetCommand(...)` 写输出缓存、`GetOutput()` 读缓存。
- **调用顺序**：常驻 Runner `Enter→Run→TryExit→Exit→End`；motion Runner 额外在首尾包 `SetupContext→...→TeardownContext`；状态枚举 `RunnerState`(kRunning/kTryExit/kFault)、`TransitionState`(kCompleted/kTrying/kFailed/kRestoreRunning)。
- **RL 行走示例要点**（`RlWalkingExampleRunner`，继承 `MotionRunner`）：`SetupContext` 中把 `data_store_->parallel_by_classic_parser` 置 false（串联训练策略要求；脚踝两种转换模式：经典 MIT 串并转换 `True`、力矩转换 `False`，不支持直接下发电机层指令）；`Enter()` 中按 `param_tag_` 校验并用 `ParamManager::create<T>()` 动态重载参数；`math::MNNModel` 加载 `.mnn` 策略（路径 `GlobalPathManager::GetConfigPath()` + `policy_file`）。
- **输入/输出链路**：从 `data_store_` 读取 `joint_info.GetState(JointInfoType::kPosition/kVelocity)`、`imu_info`（安装偏置→基座系姿态/角速度/重力投影）；手柄指令经缩放与一阶低通滤波（`enable_remote_command_lpf`）；`Run()` 推理后经 `GetMutableOutput().SetCommand(q_des, qd_des, kp, kd, tau_ff)` 写局部缓存，Task Manager 每周期汇总所有激活 Runner 做插值/奇异点/扭矩限制后同步下发电机。
- **控制输入**：由 `src/runner/input_command_arbiter` 的 `InputCommandArbiterRunner` 统一管理，已注册 `gamepad`、`virtual_gamepad` 两个 Adapter，按注册顺序（低→高优先级）仲裁；新增输入需写 Adapter 并 `RegisterInputSource(...)`。
- **ROS2 接入**：ROS2 是外挂模块，经 `ros2_bridge` 桥接；新增 Node 在 `src/ros2_node`、新增 Topic 在 node 内 publish/subscribe、新增 Msg 在 `src/protocol`；配置文件示例 `assets/<robot>/ros2_bridge/default.yaml`（注意与其余 `assets/config/<robot>/` 路径写法不一致），需在 `activated_node` 激活 node，并在 `publish_topics`/`subscribe_topics` 增加映射。
- **ros2_bridge 配置示例中出现的接口**：`/motion/node_control`（订阅）；`hardware_interface_node` 发布 `/hardware/imu_info`、`/hardware/gamepad_keys`、`/hardware/motor_debug`、`/hardware/power_info`、`/hardware/motor_state`、`/hardware/motor_command`、`/hardware/joint_state`、`/hardware/joint_command_feedback`，订阅 `/hardware/led_control`；`period: 0.002`，`mapping_periods`（joint_state 0.002 / gamepad_keys 0.02 / motor_debug 0.01 / power_info 0.05）。
- **启动流程**：文档仅给流程图 `assets/3-源码解析-01.png`，无文字步骤（文档未提及文字版流程）。

### [4-自定义-Runner.md](../t800-online/native-sdk/4-自定义-Runner.md)
- 标题：4. 自定义 Runner
- 四步流程：拷贝 `src/runner/passive`→`src/runner/demo`、`src/data/_param/passive_param`→`demo_param`、`assets/config/<robot>/passive/default.yaml`→`demo/default.yaml`。
- 关键替换：参数类名与默认 tag（`PassiveParam("passive")`→`DemoParam("demo")`）、Runner 中参数类型、注册宏 `REGISTER_RUNNER(DemoRunner, "demo_runner", kMotion)`（名字必须与 `task_motion` 的 `runner[].name` 一致）、配置路径。
- 在 `mode.yaml`（sim/robot 两份）加 `tag: demo` + `scope: demo/default.yaml`；在 `task_motion/*.yaml` 挂载 `motion: demo`、`period: 0.002`、`runner[].name/param_tag`、`manual_transition`、`key: [LB, X]`。
- 参数扩展：YAML 加字段（如 `policy_file`）→ 参数类 `LOAD_PARAM(policy_file)` + `Update()` → Runner `Enter()` 中 `ParamManager::create<DemoParam>()` + `MNNModel` 加载；可补 `Check()` 做范围/维度校验。
- 逻辑约定：`motion runner` 维护 `SetupContext()/TeardownContext()`；`Run()` 持续 `GetMutableOutput().SetCommand(...)`；耗时复位放 `TryExit`，一次性清理放 `Exit`。
- 关键接口：`BasicParam`、`LOAD_PARAM`、`ParamManager::create<T>`、`math::MNNModel`、`GetMutableOutput().SetCommand`、`REGISTER_RUNNER`。

### [03-·-故障排查：网络-Topic-日志-软硬件判断.md](../t800-online/support/03-·-故障排查：网络-Topic-日志-软硬件判断.md)
- 标题：03 · 故障排查：网络 / Topic / 日志 / 软硬件判断
- 问题反馈规范：需给出机型、固件/SDK 版本、复现步骤、实际/预期现象、完整日志、配置文件、改动项；开发者自研业务逻辑不符预期一般不在支持范围。
- 软硬件判断：单项设备异常、重启仍异常、恢复默认配置仍异常 → 考虑硬件；先停机记录故障码/条件，不要自行拆机或带电插拔。
- SSH 排查顺序：`ping <robot-ip>` → 机器人本机 `systemctl status ssh` → `nc -zv <robot-ip> 22` → `ip addr`/`ip route` → `ip neigh`；区分 ping 不通（网络/IP/网线）、通但 SSH 不通（服务/防火墙/端口）、频繁断开（网络/负载）。
- ROS2 看不到 Topic：检查物理连通、source 环境、DDS/RMW、`ROS_DOMAIN_ID`、网卡、防火墙、UDP、Multicast、网络拓扑；`ROS_LOCALHOST_ONLY=1` 会限制本机、跨机必须为 0。
- Topic 无数据：`ros2 topic info /xxx [-v]` 看 Publisher/Subscriber 与 Reliability/Durability/History/Depth，再 `ros2 topic echo`；QoS 不匹配时可按发布者策略订阅（如 `--qos-reliability best_effort`）；传感器常用 BEST_EFFORT/VOLATILE/KEEP_LAST。
- 频率/带宽：`ros2 topic hz /xxx`、`ros2 topic bw /xxx`；排查相机导致带宽/CPU/丢包问题。
- 标定资料：相机内参经 `/camera/cam_head/color/camera_info` 或 TF（`ros2 run tf2_tools view_frames`、`tf2_echo`）获取；T800 雷达驱动标定 YAML 字段 `A11/A22/A12/u0/v0`（相机内参）、`Tcl_0/Tcl_1`（LiDAR-Camera 外参）、`T_cl_cr`（左右相机外参）。
- 日志/服务：`journalctl -f`、`journalctl -u robotics.service`、`journalctl --since "10 minutes ago"`；`dmesg [-w]`、`dmesg | grep -i error|usb|eth|can`；`systemctl status robotics.service`、`systemctl --type=service`、`ps aux | grep <process>`、`top/htop`、`free -h/df -h`、`ip -s link`。
- 高负载重点关注公式：分辨率 × FPS × 数据类型 × Topic 数量 × DDS 转发范围。
- 关键命令：`ros2 topic info/echo/hz/bw`、`journalctl -u robotics.service`、`dmesg`、`systemctl status robotics.service`。
