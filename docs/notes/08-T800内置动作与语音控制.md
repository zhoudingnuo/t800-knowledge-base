# 08 - T800 内置动作调研 + 四个自定义动作（点头/挥手/握手/比心，语音可控）

> 2026-10-04。两部分：① 出厂"内置动作"到底有什么（读出厂配置 + 系统日志的结论）；
> ② 在这台 T800 Pro 上落地的 4 个上肢动作与语音控制（`robot_control/bridge/t800_actions.py`）。

## 1 出厂内置动作调研

**本机（T800 Pro，model_num 0x05，固件 1.0.2）实际开放的只有 6 个运动状态**，没有可直接调用的
表演动作（跳舞/打拳等）。依据：

- `/apps/engineai_robotics/assets/resource/rc02/t800pro/release.json`：`motions` 只有
  `idle / passive / pd_stand / rl_basic / joint_bridge / lower_body_balance`，`skills` 全空；
- 实测 `/motion/motion_state`：passive 下可切目标 = idle / pd_stand / joint_bridge，与配置一致。

**但系统里有动作能力，只是 Pro 配置没启用**：

- 控制机 lib 里带动作运行库：`libsrc_runner_rl_dance.so`（跳舞）、`rl_mimic`/`rl_mimic_mjlab`/
  `rl_longmimic`（动作模仿）、`rl_mimic_boxing(_classic)`（拳击）、`dynamic_motion_plan`；
- 同目录 **T800 开发版**（0x04）的 `release.json` 配了一整套技能（手柄组合键触发）：debut、左右轻拳、
  升龙拳、左前踢、全身技、放松动作等，还有拳击/滑步连招/战鼓舞（mjlab zhanguwu）/跪起等 mimic 状态；
  PM01 配置里直接有 `rl_mimic_dance`。技能用 LoRa 手柄组合键触发（如 `CROSS_X_UP + A` = debut）；
- Native SDK 的 t800 配置自带 dance 任务示例（`rl_dance_example`：dance.mnn + dance.npz 编排轨迹）。

**给开发者的正规动作接口**（两条，均在 `lower_body_balance` 模式下生效）：

| 接口 | 话题 | 特点 |
|---|---|---|
| 上肢运动规划 | `/motion/joint_motion_plan/request` | 发一次请求（关键帧队列 + execution_time），规划器自动执行；官方示例就是握手/挥手 |
| 上肢覆盖控制 | `/motion/joint_override_command` | 开发者 100Hz 持续发布（JointOverrideCommand，weight=1.0）；适合挥手、指向、往复运动 |

**关键证据（为什么动作只能在 lower_body_balance）**：.163 系统日志里，
进入 lower_body_balance 时出现 `dynamic_motion_plan_runner: Set joint_override_allowed_indices
with 31 joints`，离开时 `Cleared`；同时 `JointOverrideConverter initialized with 43 joints`
（初始化接受全部 43 关节）。31 = J12–J42，正是上肢 + 头 + 灵巧手的全集。

## 2 四个动作的实现（本仓库）

**选型**：覆盖控制（`/motion/joint_override_command`）。理由：不像运动规划那样需要维护
request_id/状态机；且支持头（点头）和手指（握手轻握）——规划接口的 Pro 示例只有 13 个上肢关节。

**动作数据** `robot_control/bridge/t800_actions.py`：

- `NEUTRAL` 中立位取官方示例默认值（左臂 J13–17 = 0.024/0.081/-0.001/-0.069/0，右臂 J27–31 同理）；
- `GAINS` 刚度/阻尼按官方示例：腰 500/10、臂 40/1、头 100/3、手 20/0.2；
- 关键帧按"段"定义（时长 + 只写要动的关节，由 `plan()` 向前继承成完整帧）：

| 动作 | 时长 | 来源 |
|---|---|---|
| 点头 nod | 2.2s | J41 俯仰 +0.30/-0.06/+0.28/-0.05/0（MuJoCo 渲染确认 + 为低头） |
| 挥手 wave | 4.0s | 官方 `t800/motion_plan_wave_hands.yaml`（左臂索引与 Pro 相同）：抬臂 J13=-1.296/J14=1.180/J16=-1.066，摆动时 J16 在 -1.066↔-1.834 交替 |
| 握手 shake_hand | 4.8s | 官方 `t800pro/motion_plan_shake_hand.yaml` 伸右手位姿（J27=-0.47/J28=0.255/J30=-0.731）+ 手指轻握（J34..J40 0.5~0.9）+ J27 ±0.05 摆动 2 次 |
| 比心 heart | 6.2s | 官方 MuJoCo 模型上数值 IK：双手在头顶合拢（目标 x=0.05, y=±0.035, z=1.85），肘部外张；渲染确认后写入。幅度 J13=-2.843/J16=-0.98（限位 -3.229/-2.295 内） |

**离线校验（不上真机）**：
- `python3 bridge/t800_actions.py check`：全部关键帧在 URDF 限位内；
- `tools/render_actions.py`（本机 sim/.venv 的 MuJoCo + 官方 t800pro MJCF）：把每个关键帧渲染成
  `/tmp/action_poses/*_sheet.png` 逐帧目检；比心的双臂位形就是在这个模型上求解/调出来的。

**播放器**（`bridge/bridge.py`，.163）：

- 100Hz 定时器，余弦缓入缓出插值补间；发 `JointOverrideCommand(weight=1.0)`；
- 播完保持 80ms 后发 **weight=0** 释放（SDK 里 `IsEnable()==weight!=0`）；
- 硬性前置：`mode == 'lower_body_balance'`，否则拒绝并回 `{"t":"err","msg":"当前模式 X，…"}`；
- 中止条件：模式变化（on_ms 检测）/ `{"t":"action_stop"}` / 播放超时（动作时长+1.5s）；
- 同一时刻只允许一个动作；hello 消息带 `actions` 时长表。

**语音链路**：`t800_agent.py` 新增工具 `do_action(name)` / `stop_action()`（别名解析 nod/点头/
挥挥手/握手/比心…），提示词含"动作失败要把原因说给用户，不要假装做了"。ASR → Agent → 工具 →
（播放 + TTS 播报回复）。

## 3 实机验证与注意事项

- 已验证（passive 模式下，不动）：hello.actions 正常、未知动作报错、模式门控拒绝、四个动作的
  语音指令都能正确路由并在播报里说明"需要下肢平衡模式"（`tool do_action` 出现在 mic_bridge 日志）；
  `/motion/joint_override_command` 话题 1 发布者（bridge）+ 1 订阅者（运控）。
- **待真机验证**（需 lower_body_balance）：把机器人切到 `lower_body_balance`（面板：passive →
  pd_stand → rl_basic → lower_body_balance 逐级切换；或手柄），**吊架/清场**后说"点点头"先试小动作。
- 安全兜底：动作中切模式/急停会立即释放覆盖；bridge 进程若中途挂掉，覆盖命令停止刷新，
  机器人平衡控制器接管（必要时按模式切换/passive 兜底）。
