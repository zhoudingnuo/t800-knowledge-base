## 三、关键技术成果

1. **官方 ONNX 策略接入**：从 rl_lab 源码复原其 1128 维观测布局
   （15×(关节位置23+速度23+动作23+角速度3+重力3)+指令3），可在任意 MuJoCo 仿真中运行官方策略
   （`sim/eval/run_official_onnx.py`）。
2. **行为克隆蒸馏管线**（`sim/train/distill_official.py`）：在官方策略的稳定区间采集 256k 样本 →
   训练我们自己的网络（动作 MSE **7e-4**）→ PPO 微调后精确跟踪指令速度。
3. **仿真对齐官方模型**：脚部碰撞改为官方同款 mesh convexHull、接触软化（solref 0.05）、
   质量/惯量与官方 USD **逐项一致**（84.988 kg）、官方行走增益（kp=180/40）。
4. **修复的 4 个训练侧 bug**（每个都曾导致数轮训练无效）：参考数据加载条件、参考步态掩码
   双重权限、姿态惩罚目标错误、评测链路未复现观测归一化/掩码/命令。

## 四、未完成项与根因（证据链）

**未完成**：稳定行走、行走中的长距离搬运。

**根因**：MuJoCo 与 PhysX 的接触/求解器动力学差异。

| 证据 | 结果 |
| --- | --- |
| 官方预训练策略（Isaac Lab 中稳定行走）在**我们的 MuJoCo** 中 | 100Hz 下 1.4-2.9s；400Hz 下 8.1s 原地踏步 |
| URDF vs 官方 USD 逐连杆质量/惯量 | **完全一致**（84.988 kg） |
| 关节约定 | FK 验证参考动作的 swing 足端前移 +0.22~0.34m ✓ 正确 |
| 结论 | 差异在引擎（接触模型/求解器），非控制器、参考动作、关节约定或模型参数 |

**消除该差异的唯一路径（Isaac Lab）被阻塞**：Isaac Sim 5.1 与本机驱动 595.91 不兼容
（`librtx.scenedb.plugin.so` 启动段错误；已排除环境变量、显示（Xvfb/真实）、8 组禁用参数；
Vulkan 正常）。修复需降级整机 NVIDIA 驱动 —— 你已选择暂不降级。

## 五、如何使用（常用命令）

```bash
cd /home/admin2/t800/sim

# 重建模型与场景（幂等）
.venv/bin/python build/build_t800_mjcf.py && .venv/bin/python build/make_scenes.py

# 训练（示例：参考步态 + 残差 RL，400Hz）
REF_GAIT=1 REF_GAIT_RESIDUAL=0.2 DT_CFG=0.0005 DEC_CFG=5 RESET_NOISE=0.1 \
  VX_RANGE=0.4,0.55 W_TRACK=5.0 GAMMA=0.995 ./run_train.sh myrun --walk_tune \
  --xml scene_walk_walkgains.xml --num_envs 512 --num_steps 48 --total_iters 2000

# 评测 + 录像（必须与训练同配置：DT/DEC、掩码、场景）
DT_CFG=0.0005 DEC_CFG=5 TRAIN_XML=scene_walk_walkgains.xml VIS_XML=scene_walk_vis_walkgains.xml \
  .venv/bin/python eval/render_replay.py --mode walk --ckpt runs/<run>/ckpt_XXXX.pkl \
  --vx 0.45 --seconds 10 --video runs/demo/out.mp4

# 运行官方预训练策略
.venv/bin/python eval/run_official_onnx.py --xml scene_walk_walkgains.xml --vx 0.5 --seconds 20

# 持载荷（提东西）
.venv/bin/python eval/render_replay.py --mode stand --ckpt runs/carry/ckpt_000400.pkl \
  --payload 6.0 --seconds 10 --video runs/demo/carry_6kg.mp4
```

## 六、后续可选路径（按优先级）

1. **降级驱动启动 Isaac Sim**（你已暂缓）：`apt install nvidia-driver-580-open` → 停止 Xorg 与
   GPU 占用进程 → 重载模块/重启 → 在 `isaac_ws/.venv311` 中运行官方 rl_lab 的
   `scripts/amp/play.py --task AMP-Flat-T800-v1 --load_run 2026-09-14_20-18-10 --checkpoint model_19999.pt`
   验证稳定行走，再将其关节轨迹作为参考动作蒸馏回 MuJoCo（本仓库的蒸馏管线已就绪）。
2. **在 MuJoCo 侧继续逼近 PhysX**：当前已对齐质量/惯量/脚部几何/接触软化；可继续尝试
   TGS 风格求解器参数、更软的接触、或 mujoco_warp 的迭代配置。
3. **提高控制频率下的训练**：官方策略在 400Hz 存活 8.1s，说明高频控制下本仿真更稳定；
   可在 400-1250Hz 下训练更长回合的策略（本仓库支持 `DT_CFG`/`DEC_CFG`）。
