# 06 - T800 雷达与深度相机（Odin2 激光雷达相机）实机接入

> 2026-10-04 实机验证。T800 Pro 头部的视觉/雷达是**一颗 Odin2 激光雷达相机**（dToF 点云 + 双目 RGB + IMU + 里程计一体），
> 挂在**应用计算单元 .162** 上（不是 PM01 的 D435i，也不是运控单元 .163）。本文记录：怎么连、用什么驱动、
> 官方驱动发现不了设备的坑（根因=打包 SDK 版本不兼容）、已验证的查看通路，以及可直接复制的命令。

## 1. 硬件与网络拓扑

```
Odin2（头部，firmware 3.1.3，SN P060300004，静态 IP 192.168.100.251，gw 192.168.100.1）
   │  网线，192.168.100.0/24 传感网段（设备没有 DHCP；MAC 每次启动随机变化）
   ▼
应用计算单元 .162（Jetson Orin NX，ubuntu/ubuntu）
   eno1  192.168.100.162/24   ← 接 Odin2，驱动必须在这台、用这块网卡跑
   eth1  192.168.0.162/24     ← 机器人内网（SSH 入口）
```

要点：

- **设备自带 Web 面板**：`http://192.168.100.251:8080`（Odin Dashboard，只在 .162 网段可访问）。
- 面板/HTTP API（实测可用）：`/api/version`、`/api/monitor`（各传感器实时 fps/温度）、`/api/network`、
  `/api/reboot`（**POST 必须带 JSON body，如 `-d '{}'`，否则 411**）、`/api/file/download/calib`（标定 YAML）、
  `/api/file/download/log`（私有签名格式，不是普通 tar.gz）、`/api/ota/*`。
- `/api/monitor` 实测：LiDAR 10Hz、RGB-0/1 30Hz、IMU 400Hz、SLAM 10Hz、ODOM-L 10Hz、ODOM-H 400Hz、TF 全绿。
- 标定（`/api/file/download/calib`）：`cam_model: FishPoly`、双目 640×544、基线 50.6493 mm、FOV 100°；
  驱动日志里同样打印 StereoRectifier 参数（新焦距 268.5 px）。

## 2. 驱动：用哪个、怎么起

### 2.1 结论先说

| 驱动来源 | 结果 |
|---|---|
| 系统自带 deb `engineai-odin2-ros-humble-driver 0.11.0`（`/opt/ros/humble`，engineai-odin2-sdk **2.0.3**） | ❌ UDP 发现 0 设备，永远连不上 |
| 厂商工作区 `~/odin_latest`（2026-09-29 构建，厂商 SDK **3.3.0_20260822**） | ✅ 秒发现、正常出流（本文采用） |

两个 SDK 的 `odin_hotplug` 工具同时对比验证过：同样的网络、同样的设备，2.0.3 报 `found 0 device(s)`，
3.3.0 立刻 `Device arrived - IP=192.168.100.251, SN=P060300004`。**属于 SDK/固件兼容问题，不是设备故障**
（设备 HTTP、TCP 60001/60002、ping、内部传感器流水线全部正常；重启设备无效）。

### 2.2 启动命令（在 .162 上，后台常驻）

```bash
# 每次 SSH 会话（.162）先准备环境
export ROS_DOMAIN_ID=69 RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
source /opt/ros/humble/setup.bash
source ~/odin_latest/install/setup.bash          # 关键：让 odin_ros_driver_rev1 指向厂商工作区
ros2 pkg prefix odin_ros_driver_rev1              # 应输出 /home/ubuntu/odin_latest/install/odin_ros_driver_rev1

# 启动（不带 RViz；日志 ~/odin_vendor_driver.log）
nohup setsid ros2 launch odin_ros_driver_rev1 driver.launch.py start_rviz:=false \
  > ~/odin_vendor_driver.log 2>&1 < /dev/null &

# 停止
pkill -f "ros2 launch odin_ros_driver"; pkill -f odin_ros_driver_node
```

从本机一键（经 Orin 两跳）：

```bash
ssh orin 'sshpass -p ubuntu ssh ubuntu@192.168.0.162 "bash -s"' <<'EOF'
export ROS_DOMAIN_ID=69 RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
source /opt/ros/humble/setup.bash; source ~/odin_latest/install/setup.bash
nohup setsid ros2 launch odin_ros_driver_rev1 driver.launch.py start_rviz:=false > ~/odin_vendor_driver.log 2>&1 < /dev/null &
EOF
```

### 2.3 为什么不能用 .163 / Orin 跑驱动

设备发现走 **UDP 广播（`255.255.255.255:60001`，cmd_id=0x01）**，只有和 Odin2 同 L2 网段（192.168.100.0/24）
的主机能收到应答。.163 和 Orin 都没有该网段接口，所以驱动只能在 **.162** 上跑。
（.162 上跑驱动后，数据经 ROS2 DDS 出到 domain 69；.163 上能正常订阅这些话题。）

## 3. 话题与实测帧率（厂商驱动）

前缀 `/manifold/ODIN2/device0/`，帧率 2026-10-04 实测：

| 话题 | 说明 | 实测 |
|---|---|---|
| `cloud/raw` | 原始 dToF 点云 | 10.25 Hz |
| `cloud/slam` | SLAM 点云（IMU 系） | 10 Hz |
| `cloud/render` | 彩色渲染点云（相机着色） | 10 Hz |
| `camera0/compressed` | 左相机 JPEG（网络传输用这个） | 30 Hz |
| `camera0/raw` | 左相机解码后 raw | 30.7 Hz |
| `camera0/rect`、`camera0/undistort`、`camera0/opencv_undistort`、`camera0/camera_info` | 校正/去畸变/内参 | — |
| `camera1/*` | 右相机（同上成套） | 30 Hz |
| `imu` | IMU | 399 Hz |
| `odometry_lf` / `odometry_hf` | 低频/高频里程计 | 10 / 400 Hz |
| `gray`、`diag_status` | 灰度图、诊断 | — |
| `/manifold/driver/device_online`、`device_offline`、`resolution_change` | 设备热插拔事件 | — |

**点云规格实测**（2026-10-04，`.162` 上直读 `cloud/raw`）：

- **192 线 × 256 点 = 49152 点/帧**（ROS 消息为非结构化 `height=1`，`point_step=18`），帧率 10 Hz；
- 有效点约 **3.5 万/帧（70.8%）**，≈ 35 万有效点/秒；
- FOV：**水平 133°（-65.6°~+67.5°）× 垂直 86°（-38.2°~+47.8°）**，角分辨率 ≈0.52°(H)/0.45°(V)；
- 每点字段：`x/y/z`(f32) + `intensity`(u8, 10~231) + `confidence`(u8) + **`offset_time`(f32 逐点时间，0~94.4ms、31 级量化)**；
- 本帧最近有效点 1.75 m（dToF 有近距盲区，滤点参数 `blind` 别设太小）；
- `frame_id=device0/lidar`，`/tf` 有发布（含传感器外参）。

其他要点：

- 图像 640×544、默认 frame_id `odom`；点云 256×192。
- 网络侧传的是 **压缩图（jpeg）**；`raw/undistort/rect` 由 `post_process_node` 在本机解码生成（Jetson 硬解 NvJpeg）。
- 录制大量高频话题时用 `~/odin/src/ros_driver/config/rosbag2_qos.yaml` 做 QoS 覆盖（官方提供）。
- 点云+双相机全开经 Orin WiFi 中转约 **3.6 MB/s**（点云 10Hz≈1.0MB/s + 图像 16 张/s≈2.6MB/s），
  链路实测余量充足（WiFi TX 175 Mbps）。

## 4. 本机查看（已验证通路）

### 4.1 官方 Lichtblick/Foxglove 网页版（机器人自带，0 配置）

.162 上常驻：Caddy 在 **:9003** 提供 Lichtblick 网页应用，foxglove_bridge 在 **:8765**（随机器人应用自启动）。
本机经 Orin 做端口转发即可：

```bash
ssh -N -L 127.0.0.1:9003:192.168.0.162:9003 -L 127.0.0.1:8765:192.168.0.162:8765 orin &
# 浏览器打开 http://127.0.0.1:9003 → "Open connection" → Foxglove WebSocket → ws://localhost:8765
```

实测可连、有实时时间戳；面板里加 **3D**（topic 选 `cloud/raw`/`cloud/render`）和 **Image**（选 `camera0/compressed`）即可看图。
机器人还内置了一套关节曲线布局。注意：这是"借用官方软件"的临时方案。

### 4.2 自研查看器（已集成进 robot_control）

不使用官方软件，走与关节控制相同的三段式架构（启动命令与协议详见 `robot_control/README.md`「雷达 / 相机查看」一节）：

```
Electron 面板(本机) ──TCP:9802──▶ Orin relay ──▶ .162 odin_bridge.py(ROS2↔TCP) ──▶ /manifold/ODIN2/device0/*
```

- `.162`：`robot_control/bridge/odin_bridge.py`（已部署 `~/t800_odin/`）—— 订阅点云与压缩图，
  按"JSON 头行 + 定长二进制负载"推流（点云抽稀后发 f32 xyz，图像直接转发设备 JPEG）；
- `Orin`：`robot_control/relay/relay.py` 复用（第二实例，9802 → .162:9802）；
- 本机：`robot_control/app/` 面板新增「雷达 / 相机」页 —— 点云 3D 视图（拖转/缩放/着色/网格）+
  相机 0/1 实时图；**打开面板即自动连接，断线 3s 自动重连**。

2026-10-04 实机验证：点云 10Hz（抽稀 1/4 ≈ 8700 点/帧）+ 双相机 8Hz 稳定显示，
链路占用 ~3.6MB/s，连接长稳（55s+ 无掉线）。

## 5. 关键坑（实机踩过）

1. **Orin 的 WiFi 必须先切回机器人热点**：Orin 平时连 `AIRS-Free`（无 192.168.0.x 路由，机器人整个失联）。
   修复：`ssh orin 'echo 123 | sudo -S nmcli con up Robot_Wifi_T800_29C_0313'`（普通用户 `nmcli` 会报
   "Not authorized to control networking"，必须 sudo；切走后 eno1 上的 SSH 仍可用）。
   注意：热点 SSID 有时**扫不到但能连上**，以 `nmcli con up` 结果为准。
2. **系统自带的 odin 驱动（SDK 2.0.3）发现不了设备**——见第 2 节，改用 `~/odin_latest` 工作区。
   该工作区是 2026-09-29 从 `ros_driver_v3.4.0_beta_*.tar.xz` 构建的，旧版备份在
   `~/odin_latest_3.3.0_backup_20260929162032`（其 `driver.log` 是正常工作的日志样本，可对照排障）。
3. **设备 MAC 每次启动都变**（ARP 里观察到 3 个不同 MAC），不要用 MAC 做标识，用 SN。
4. **`/api/reboot` 不带 body 会 411**：`curl -X POST -H 'Content-Type: application/json' -d '{}' http://192.168.100.251:8080/api/reboot`。
5. **直连诊断（仅供排障）**：手工构造 `DiscoveredDevice{sn,model,ip,host_ip,network}` 直接调
   `ConnectDevice()` 可以连上（返回 handle），`GetNetworkAttribute` rc=0（走 HTTP），但 `SetOperatingMode`
   超时（rc=4）——说明 TCP 命令通道"能连不应答"，是 SDK 2.0.3 的兼容性问题表现，正常用厂商 SDK 时不会遇到。
6. **设备日志**是签名二进制（`V1.0.0 vector::...`），不要当 tar.gz 解；标定 YAML 可直接下载使用。
7. 驱动在 .162 上跑起来后，**跨主机 DDS 的老问题仍在**：读话题请在 .162（或已确认发现正常的机器）上做，
   详见 `04-Orin中转真机控制.md` 第 6 节。
8. **自写 TCP 推流服务的"2 秒断连"**：odin_bridge 发送线程给 socket `settimeout(2.0)` 防止慢客户端卡死，
   但读线程 `recv` 复用同一个 socket，空闲 2s 就抛 `socket.timeout`（`OSError` 子类）被当成错误关闭——
   现象是客户端每 2s 掉线重连一次。读循环必须 `except socket.timeout: continue`。
9. **不要在关节控制进行中动面板窗口**：面板「下发」开着时点击任何按钮都可能影响机器人，
   调试雷达页前先确认顶栏「下发: 关」。
